## 0. 一句话结论

前端页面**只需要对接一套 HTTP 接口**：`/api/*`。  
数据库和 Flask 之间靠 SQLAlchemy，不是 HTTP 接口，前端永远不直接碰数据库。

```
浏览器页面（HTML / DOM / JS）
        │  HTTP + JSON        ← 前端和 Flask 的接口
        ▼
Flask 路由 routes/*.py
        │  SQLAlchemy ORM    ← Flask 和数据库的连接方式
        ▼
SQLite 文件 backend/data/security.db
```

## 2. 通用约定

### 2.1 后端地址

默认：

```
http://127.0.0.1:5000
```

如需覆盖，在加载页面模块之前加：

```html
<script>
  window.SAP_API_BASE = "http://192.168.1.10:5000";
</script>
```

### 2.2 统一响应结构

所有接口都返回：

```json
{
  "code": 200,
  "message": "success",
  "data": {},
  "errors": []
}
```

- `code` 与 HTTP 状态码一致
- `errors` 只在参数校验失败时出现，结构为 `[{"field": "...", "message": "..."}]`
- 前端判断成功以 `response.ok` 和 `json.code` 为准

### 2.3 登录凭证

登录/注册成功后返回：

```json
{
  "user": {
    "id": 1,
    "username": "tester",
    "role": "user",
    "created_at": "2026-11-19 22:46:12"
  },
  "token": "1.1799999999.签名串"
}
```

之后所有需要登录的接口都要带：

```
Authorization: Bearer <token>
```

注意：

- 不支持 `?token=xxx`，token 不能放在 URL 里
- token 默认 7 天有效
- 前端 token 存在 `localStorage` 的 `sap_token`
- 用户信息存在 `sap_user`

### 2.4 分页

查询参数：

| 参数 | 默认 | 上限 | 说明 |
|---|---:|---:|---|
| `page` | 1 | - | 页码，从 1 开始 |
| `pagesize` | 10 | 100 | 每页条数 |

分页响应：

```json
{
  "list": [],
  "total": 0,
  "page": 1,
  "pagesize": 10,
  "total_pages": 0
}
```

### 2.5 时间格式

后端返回的时间统一是：

```
YYYY-MM-DD HH:mm:ss
```

例如：`2026-11-19 22:46:12`

### 2.6 状态码约定

| HTTP | 含义 | 前端处理 |
|---:|---|---|
| 200 | 成功 | 正常渲染 |
| 400 | 参数错误 | 显示 `errors[].message` |
| 401 | 未登录 / token 过期 | 清除 token，提示登录；可降级本地 |
| 403 | 无权限（如普通用户查审计日志） | 提示“无权限” |
| 404 | 资源不存在 / 无权查看 | 提示“记录不存在或无权查看” |
| 409 | 用户名已存在 | 提示换用户名 |
| 500 | 服务器错误 | 提示稍后重试；可降级本地 |

### 2.7 降级原则

| 场景 | 前端行为 |
|---|---|
| 未登录 | 扫描功能照常，结果存 `localStorage` |
| 后端没启动 | 页面显示“后端不可用 · 本地模式”，结果存本地 |
| 请求超时 | 同“后端不可用” |
| 401 | 清除登录态，改存本地 |
| 500 | 提示错误，必要时改存本地 |

## 4. 接口详情

### 4.1 探活

**GET** `/api/ping`

不需要登录，用来判断后端是否在线。

响应：

```json
{
  "code": 200,
  "message": "pong",
  "data": {
    "time": "2026-11-19 22:46:00"
  }
}
```

### 4.2 健康检查

**GET** `/api/health`

检查数据库是否可用。

正常：

```json
{
  "code": 200,
  "message": "后端在线",
  "data": {
    "status": "ok",
    "db": "ok",
    "version": "1.0.0"
  }
}
```

数据库不可用时返回 `503`。

### 4.3 注册

**POST** `/api/auth/register`

请求：

```json
{
  "username": "tester",
  "password": "abc123456"
}
```

规则：

- 用户名 3-20 位，只能是字母、数字、下划线
- 密码 6-32 位
- 密码不能和用户名相同

成功响应：

```json
{
  "code": 200,
  "message": "注册成功",
  "data": {
    "user": {
      "id": 1,
      "username": "tester",
      "role": "user",
      "created_at": "2026-11-19 22:46:12"
    },
    "token": "1.1799999999.签名串"
  }
}
```

失败示例：

```json
{
  "code": 400,
  "message": "参数校验失败",
  "data": null,
  "errors": [
    { "field": "username", "message": "用户名只能包含字母、数字、下划线，长度 3-20" }
  ]
}
```

用户名重复返回 `409`。

### 4.4 登录

**POST** `/api/auth/login`

请求：

```json
{
  "username": "tester",
  "password": "abc123456"
}
```

成功响应结构同注册。  
失败统一返回 `401`：

```json
{
  "code": 401,
  "message": "用户名或密码错误",
  "data": null
}
```

不会提示“用户不存在”还是“密码错误”，防止账号枚举。

### 4.5 当前用户

**GET** `/api/auth/me`

请求头：

```
Authorization: Bearer <token>
```

成功：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "id": 1,
    "username": "tester",
    "role": "user",
    "created_at": "2026-11-19 22:46:12"
  }
}
```

token 无效或过期返回 `401`。

### 4.6 保存文件审计结果

**POST** `/api/reports/save`

需要登录。  
请求体就是前端 `scan.js` 返回的 `ScanResult`：

```json
{
  "file_name": "sshd_bad.conf",
  "stat": {
    "high": 3,
    "mid": 0,
    "low": 0,
    "total": 3
  },
  "vul_list": [
    {
      "vid": "VUL001",
      "vname": "SSH 开启密码登录认证",
      "level": "高危",
      "line": 9,
      "hit_content": "PasswordAuthentication yes",
      "description": "允许密码登录会增加暴力破解风险",
      "suggestion": "改为 PasswordAuthentication no",
      "file_name": "sshd_bad.conf"
    }
  ],
  "scan_meta": {
    "file_name": "sshd_bad.conf",
    "total_lines": 40,
    "rule_count": 12,
    "rule_error_count": 0,
    "cost_ms": 5,
    "scan_time": "2026-11-19T22:48:00"
  },
  "suggestions": [
    "改为 PasswordAuthentication no"
  ]
}
```

说明：

- `file_name` 可以不传，后端会自动取 `scan_meta.file_name`
- `stat` 必须是对象，`high + mid + low` 必须等于 `total`
- `stat.total` 必须等于 `vul_list.length`
- `level` 只能是 `高危`、`中危`、`低危`
- `vul_list` 每条必须包含：
  `vid`、`vname`、`level`、`line`、`hit_content`、`description`、`suggestion`、`file_name`
- 单次最多 2000 条漏洞，报告内容最大约 2MB
- `suggestions` 可不传，后端会从 `vul_list` 的 `suggestion` 去重提取
- 保存成功会写一条审计日志：`CREATE_REPORT`

成功响应：

```json
{
  "code": 200,
  "message": "保存成功",
  "data": {
    "report_no": "2dfadcdff53b4a76",
    "report_type": "file",
    "url": null,
    "file_name": "sshd_bad.conf",
    "score": null,
    "grade": null,
    "created_at": "2026-11-19 22:48:56",
    "stat": {
      "high": 3,
      "mid": 0,
      "low": 0,
      "total": 3
    }
  }
}
```

未登录返回 `401`，前端应改存 `localStorage`。

## 5. 前端页面接入步骤（给写页面的队友）

### 5.1 页面加载顺序

页面里先加载全局工具，再加载 ES Module：

```html
<script src="../js/ui/storage.js"></script>
<script src="../js/utils/common.js"></script>
<script type="module" src="../js/pages/scan-page.js"></script>
```

`storage.js` 是普通脚本，会暴露 `window.SapStorage`。  
模块脚本在页面解析完成后执行，所以能拿到 `window.SapStorage`。

### 5.2 引入 API 模块

在 `js/pages/xxx.js` 里：

```js
import { getToken, getCurrentUser, ping } from "../api/client.js";
import { login, register, logout, me } from "../api/auth.js";
import {
  saveFileReport,
  listFileReports,
  getReport,
  deleteReport,
} from "../api/reports.js";
```

不要在页面里直接写 `fetch`。统一走 `js/api/`，以后改地址、加请求头、处理 401 都只改一处。

### 5.3 登录 / 注册

```js
const result = await login(username, password);

if (result.ok) {
  // token 和 user 已经自动存进 localStorage
  console.log("登录成功", result.data.user);
} else if (result.offline) {
  console.log("后端不可用，继续用本地模式");
} else {
  console.log("登录失败", result.message, result.errors);
}
```

注册同理：

```js
const result = await register(username, password);
```

页面加载时校验登录态：

```js
if (getToken()) {
  const result = await me();
  if (result.status === 401) {
    logout();
  }
}
```

退出：

```js
logout();
```

### 5.4 扫描并保存

```js
import { scanText } from "../core/scan.js";
import { readFileAsText } from "../core/file-reader.js";
import { saveFileReport } from "../api/reports.js";
import { saveLocalReport } from "../api/local-reports.js";
import { getToken } from "../api/client.js";

async function scanOne(file) {
  const text = await readFileAsText(file);
  const result = await scanText(text, file.name);

  // result = { vul_list, stat, scan_meta }

  if (getToken()) {
    const saved = await saveFileReport(result);
    if (saved.ok) {
      console.log("已存云端", saved.data.report_no);
      return;
    }
    if (saved.status === 401) {
      console.log("登录过期，改存本地");
    } else if (saved.offline) {
      console.log("后端不可用，改存本地");
    }
  }

  const local = saveLocalReport(result);
  console.log("已存本地", local.report_no);
}
```

关键点：

- `saveFileReport(result)` 直接把 `ScanResult` 传过去
- 不需要手动拆 `vul_list`、`stat`
- `file_name` 会自动从 `result.scan_meta.file_name` 取
- 未登录或请求失败时，调用 `saveLocalReport(result)`

### 5.5 历史记录

```js
const result = await listFileReports(1, 10);

if (result.ok) {
  result.data.list.forEach((item) => {
    console.log(item.report_no, item.file_name, item.stat);
  });
}
```

载入详情：

```js
const detail = await getReport(reportNo);
if (detail.ok) {
  const vulList = detail.data.vul_list;
  const scanMeta = detail.data.scan_meta;

```

删除：

```js
await deleteReport(reportNo);
```

列表只返回摘要；不要在列表页渲染 `vul_list`，点“详情”时再调详情接口。

### 5.6 仪表盘页面

仪表盘没有单独的汇总接口，先这样接：

```js
const result = await listFileReports(1, 100);
if (result.ok) {
  let high = 0, mid = 0, low = 0, total = 0;

  result.data.list.forEach((item) => {
    const stat = item.stat || {};
    high += stat.high || 0;
    mid += stat.mid || 0;
    low += stat.low || 0;
    total += stat.total || 0;
  });

  // 渲染到 #high-risk-count / #mid-risk-count / #low-risk-count
  // 最近 5 条：result.data.list.slice(0, 5)
}
```

注意：`pagesize` 最大 100。报告超过 100 条时，要么循环翻页，要么后端以后加 `/api/reports/summary`。

### 5.7 报告页面


### 5.8 错误处理

```js
async function callApi() {
  const result = await someApi();

  if (result.ok) return result.data;

  if (result.offline) {
    // 后端不可用：切本地模式
    return null;
  }

  if (result.status === 401) {
    // 清除登录态，提示登录
    return null;
  }

  if (result.status === 400) {
    // 表单错误：result.errors 里是 [{field, message}]
    console.log(result.errors);
    return null;
  }

  if (result.status === 403) {
    // 无权限
    return null;
  }

  // 404 / 500
  console.log(result.message);
  return null;
}
```

### 5.9 常见坑

1. **不要用 `file://` 打开页面。** ES Module、`fetch`、CORS 都会失败。
2. **不要手写 `fetch` 到页面里。** 用 `js/api/`，401/超时/降级已经封装好。
3. **不要给列表页传 `details`。** 保存接口要的是 `vul_list` + `stat` + `scan_meta`。
4. **`stat.total` 必须等于 `vul_list.length`**，否则 400。
5. **`level` 必须是中文**：`高危`、`中危`、`低危`。
6. **文件历史用 `report_type=file`**，URL 检测历史用 `/api/scanner/history`。
7. **普通用户不能查审计日志**，401/403 不是 bug。
8. **token 不要放 URL**，只能放 `Authorization` 请求头。
9. **后端没启动时先看 `/api/ping`**，不要先怀疑代码。
10. **浏览器 Network 里 OPTIONS 失败**，通常是 CORS 或后端没启动。

### 5.10 页面接入检查清单

- [ ] 页面通过 `http://` 打开，不是 `file://`
- [ ] `storage.js` 在模块之前加载
- [ ] `/api/ping` 能通，页面显示“后端在线”
- [ ] 注册 / 登录成功，header 显示用户名
- [ ] 未登录扫描能存本地
- [ ] 登录后扫描显示“已保存到云端”
- [ ] 历史列表能刷新、载入、删除
- [ ] 刷新页面后登录态还在
- [ ] 401 时会清除 token 并提示登录
- [ ] 后端停掉后页面显示“本地模式”，仍能扫描

## 6. 后端与 JS 的对接说明（单独报告）

### 6.1 没有“另一套协议”

后端并没有“连接 JS”的另一种方式。  
浏览器里的 JS 和页面，最终都是发 HTTP 请求到 Flask：

```
页面 DOM
  └─ js/pages/scan-page.js
       ├─ js/core/file-reader.js
       ├─ js/core/scan.js
       ├─ js/api/auth.js
       ├─ js/api/reports.js
       ├─ js/api/local-reports.js
       └─ js/api/client.js  ── fetch ──> Flask /api/*
```

所以“前端页面接入”和“后端连接 JS”本质是同一件事。  
区别只是：页面负责 DOM，`js/api/` 负责 HTTP，`js/core/` 负责纯算法。

### 6.2 模块职责

| 模块 | 职责 | 不应该做什么 |
|---|---|---|
| `js/core/file-reader.js` | 读本地文件 | 不调用后端 |
| `js/core/scan.js` | 纯扫描算法，输入文本、输出 `ScanResult` | 不调用后端 |
| `js/api/client.js` | 后端地址、fetch 封装、token、超时、401 | 不操作 DOM |
| `js/api/auth.js` | 注册/登录/me/退出 | 不操作 DOM |
| `js/api/reports.js` | 报告保存/列表/详情/删除 | 不操作 DOM |
| `js/api/local-reports.js` | 本地降级存储 | 不发 HTTP |
| `js/pages/scan-page.js` | 绑定 DOM、串流程、渲染结果 | 不直接写 fetch |

### 6.3 新增一个接口的步骤

以后要加新功能，按这个顺序：

1. **后端**：在 `routes/` 加路由，在 `services/` 加业务逻辑，必要时在 `models/` 加表。
2. **后端自测**：用 PowerShell / curl 调通，确认响应结构。
3. **前端 API 层**：在 `js/api/` 里加一个函数，例如 `export function foo() { return request("/api/foo"); }`。
4. **页面层**：在 `js/pages/xxx.js` 里 import 这个函数，处理 `ok / offline / status`。
5. **降级**：如果这个功能要求离线可用，再加 localStorage 分支。
6. **文档**：把接口补进本文档。

### 6.4 数据契约

文件审计的核心契约是 `ScanResult`：

```json
{
  "vul_list": [],
  "stat": { "high": 0, "mid": 0, "low": 0, "total": 0 },
  "scan_meta": {
    "file_name": "",
    "total_lines": 0,
    "rule_count": 0,
    "rule_error_count": 0,
    "cost_ms": 0,
    "scan_time": ""
  }
}
```

后端保存后返回报告摘要，详情接口再把 `vul_list` / `scan_meta` 还回来。  
不要在前端改字段名；如果确实要改，先改 `js/core/data-schema.js` 和后端校验，再同步本文档。

### 6.5 本地存储键

| Key | 内容 |
|---|---|
| `sap_token` | 登录 token |
| `sap_user` | 当前用户信息 |
| `sap_local_reports` | 未登录/离线的本地报告，最多 20 条 |
| `sap_api_base` | 可选的后端地址覆盖 |

### 6.6 安全注意

- 前端不能保存任何密钥；token 只是登录凭证
- token 存在 localStorage，生产环境要防 XSS（CSP、输出转义）
- 后端会校验所有参数，前端校验只是为了用户体验
- 生产环境不要用 `CORS(app)` 全放开，要限制来源
- 生产环境要用 HTTPS
- 审计日志没有删除接口，前端也不要做“删除日志”按钮

### 6.7 联调排查顺序

1. 浏览器打开 `http://127.0.0.1:5000/api/ping`，确认后端在线
2. 浏览器打开前端页面，F12 → Network，看请求是否发出
3. 看 `OPTIONS` 预检是否 200
4. 看 `POST /api/reports/save` 的状态码和响应体
5. 401 → 检查 `Authorization: Bearer <token>`
6. 400 → 看 `errors` 里的字段
7. 403 → 当前账号不是 admin
8. 后端停掉 → 页面应自动显示“本地模式”

PowerShell 自测示例：

```powershell
Invoke-RestMethod http://127.0.0.1:5000/api/ping

Invoke-RestMethod -Method Post -Uri http://127.0.0.1:5000/api/auth/register `
  -ContentType 'application/json' `
  -Body '{"username":"tester","password":"abc123456"}'

$login = Invoke-RestMethod -Method Post -Uri http://127.0.0.1:5000/api/auth/login `
  -ContentType 'application/json' `
  -Body '{"username":"tester","password":"abc123456"}'

$headers = @{ Authorization = "Bearer " + $login.data.token }

Invoke-RestMethod -Uri "http://127.0.0.1:5000/api/reports?report_type=file" `
  -Headers $headers
```
