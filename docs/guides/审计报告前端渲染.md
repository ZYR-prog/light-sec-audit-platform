# 审计报告前端渲染规范（C 负责）

> 适用页面：`audit_demo/report.html`
> 参考实现：`audit_demo/report-app.js`（A 的报告页脚本，B 提供）
> 数据结构来源：`js/core/data-schema.js`、`js/core/scan.js`（B 的扫描规范）
> 后端返回结构：`backend/models/models.py` 的 `Report.to_dict()`

本文档说明**前端拿到一份扫描结果后，如何渲染成审计报告页面**，包括数据来源、字段定义、渲染分块、降级策略、安全要求和验收清单。

---

## 一、渲染目标

把一次扫描的结果渲染为一份可阅读、可打印的审计报告，包含 5 个区块：

```
┌─────────────────────────────────────────────┐
│ ① 报告头部   标题 / 文件名 / 扫描时间 / 报告编号 │
├─────────────────────────────────────────────┤
│ ② 统计区     高危 N · 中危 N · 低危 N · 合计 N   │
├─────────────────────────────────────────────┤
│ ③ 扫描元信息 规则数 / 总行数 / 耗时 / 规则错误数  │
├─────────────────────────────────────────────┤
│ ④ 漏洞明细   逐条：等级徽章 + 名称 + 位置 + 说明 + 建议 │
├─────────────────────────────────────────────┤
│ ⑤ 空状态     无漏洞 / 无数据 两种提示            │
└─────────────────────────────────────────────┘
```

---

## 二、数据来源与优先级

前端渲染只认**统一归一化后的对象**，原始数据有三个来源：

| 来源 | 取数方式 | 说明 |
| --- | --- | --- |
| 后端报告详情 | `GET /api/reports/{report_no}`（带 token） | 已登录、后端在线时的首选 |
| 本地历史 | `localStorage` 键 `sap_local_reports`，按 `report_no` 取 | 未登录或后端不可用时的降级来源 |
| 旧版扫描页传值 | `localStorage` 键 `scanResult` | 兼容旧版 `app.js` 的跳转方式（可选保留） |

优先级：**URL 参数指定的 `report_no` → 后端详情（失败降级本地）→ 本地历史 → `scanResult` → 空状态**。

> ⚠️ 注意：`scan-page.js` 存本地用的是 `sap_local_reports`，旧 `app.js` 用的是 `scanResult`，两者结构不同，进入渲染前必须归一化，不能直接混用。

## 三、数据结构规范（按 B 的扫描规范）

### 3.1 归一化后的渲染输入对象

```json
{
  "report_no": "3f9a2c1e-...",
  "report_type": "file",
  "file_name": "sshd_config",
  "stat": { "high": 1, "mid": 1, "low": 0, "total": 2 },
  "vul_list": [
    {
      "vid": "VUL004",
      "vname": "SSH 允许 root 登录",
      "level": "高危",
      "line": 10,
      "hit_content": "PermitRootLogin yes",
      "description": "允许 root 账号直接远程登录",
      "suggestion": "改为 PermitRootLogin no",
      "file_name": "sshd_config",
      "note": "多文件扫描时为对应文件"
    }
  ],
  "scan_meta": {
    "file_name": "sshd_config",
    "total_lines": 40,
    "rule_count": 18,
    "rule_error_count": 0,
    "cost_ms": 12,
    "scan_time": "2026-11-20 10:00:00"
  },
  "suggestions": "",
  "created_at": "2026-11-20T02:00:00"
}
```

### 3.2 字段约束（渲染前必须遵守）

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `stat.high / mid / low` | number | **这里用英文键**，只作统计，不做展示文案 |
| `stat.total` | number | 等于 `high + mid + low`，也等于 `vul_list.length` |
| `vul_list[].level` | string | **只允许中文三值：`高危` / `中危` / `低危`**，禁止写成 high/mid/low |
| `vul_list[].line` | number | 行号；缺失时显示 `-` |
| `vul_list[].hit_content` | string | 命中的原始内容，按代码样式展示，必须转义 |
| `scan_meta.file_name` | string 或 string[] | 多文件扫描时是数组（B 的 `report-app.js` 约定）；`scan.js` 里则是 `a.conf、b.conf 等 N 个文件` 形式的字符串 |
| `scan_meta.scan_time` | string | `YYYY-MM-DD HH:mm:ss`，**本地时间**，不是 ISO |
| `created_at` | string | 后端 ISO 时间，仅后端来源有 |

> **最容易出错的一点**：`stat` 的键是英文（high/mid/low），`level` 的值是中文（高危/中危/低危）。两者不是一回事，不要互相转换。

## 四、等级与样式映射

渲染时统一用 `level` 的中文值查表：

```js
const LEVEL_CLASS = {
  "高危": "risk-high",
  "中危": "risk-mid",
  "低危": "risk-low"
};
```

对应 CSS（`risk-badge` + 等级类，药丸形半透明底）：

| level | class | 视觉 |
| --- | --- | --- |
| 高危 | `risk-high` | 红底 15% 透明 + 亮红字 |
| 中危 | `risk-mid` | 黄底 15% 透明 + 亮黄字 |
| 低危 | `risk-low` | 绿底 15% 透明 + 亮绿字 |
| 其他/缺失 | `risk-low` | 兜底，页面不崩 |

统计卡片的颜色与徽章一致：高危红、中危黄、低危绿。

## 五、渲染分块细则

### ① 报告头部

- 标题：固定文案「安全审计报告」
- 文件名：`file_name`；数组用 `、` 连接；多文件可显示「共 N 个文件」
- 扫描时间：优先 `scan_meta.scan_time`，没有再取 `created_at`
- 报告编号：`report_no`，本地历史数据可能为空，空则不显示该行

### ② 统计区

- 直接读 `stat`，不要重新遍历 `vul_list` 计算（以 B 返回的统计为准）
- 四个数字：`high`、`mid`、`low`、`total`
- 任一字段缺失按 `0` 处理

### ③ 扫描元信息

| 展示项 | 取值 |
| --- | --- |
| 扫描规则数 | `scan_meta.rule_count` |
| 文件总行数 | `scan_meta.total_lines` |
| 扫描耗时 | `scan_meta.cost_ms` + `ms` |
| 规则错误数 | `scan_meta.rule_error_count`，大于 0 时用警示色 |

### ④ 漏洞明细（逐条渲染）

每条漏洞一个卡片或表格行，字段顺序固定：

```
[等级徽章] 漏洞名称（vname）
编号：vid        位置：file_name 第 line 行
说明：description
命中内容：hit_content（等宽字体、保留原文）
修复建议：suggestion
```

- 列表顺序保持后端返回顺序，不在前端重新排序
- 描述过长时前端截断（如 50 字），完整内容放详情弹窗
- 命中内容必须按代码块渲染，且**只转义、不解析**

### ⑤ 空状态

| 场景 | 展示 |
| --- | --- |
| `vul_list` 为空数组 | 「未检出风险项」+ 绿色提示，统计区显示全 0 |
| 完全无数据 | 「暂无报告数据，请先完成一次扫描」+ 返回扫描页链接 |

## 六、渲染流程

```
进入页面
   │
   ├─ 读取 URL 参数 report_no
   │
   ├─ 有 token 且后端在线？
   │      ├─ 是 → GET /api/reports/{report_no}
   │      │         ├─ 成功 → 归一化 → 渲染
   │      │         └─ 失败（网络/404）→ 走本地降级
   │      └─ 否 → 走本地降级
   │
   ├─ 本地降级：sap_local_reports 按 report_no 查找
   │      ├─ 找到 → 归一化 → 渲染（顶部提示"本地报告"）
   │      └─ 未找到 → 尝试旧键 scanResult
   │
   └─ 仍无数据 → 渲染空状态
```

---

## 七、安全与健壮性要求

1. **所有用户可控字符串（文件名、漏洞名、命中内容、说明、建议）一律用 `textContent` 或转义后插入，禁止直接拼 `innerHTML`**——命中内容里可能含 `<script>`。
2. 数字字段渲染前用 `Number(x) || 0` 兜底，避免 `NaN` 上屏。
3. 字段缺失时显示 `-`，不抛异常、不渲染 `undefined`。
4. `level` 非中文三值时走兜底样式，**不阻塞整份报告渲染**。
5. 打印样式：`@media print` 下隐藏侧边栏、按钮、导航，只保留报告主体。

---

## 八、与现有代码的关系

- `audit_demo/report-app.js`（B 提供）：已支持从 `localStorage` 读取并渲染，字段与本文档一致，可作参考实现。
- 其存储键为 `scanResult`，而当前扫描页 `scan-page.js` 写入的是 `sap_local_reports`，**两边键名未统一**——接入时以本文档「二、数据来源与优先级」为准，读取侧做兼容，不要改 B 的返回结构。
- `scan.html` 的结果表（`js/pages/scan-page.js`）与本报告页共用同一套 `level` 中文值和 `risk-*` 样式类。

## 九、验收清单

| # | 用例 | 预期 |
| --- | --- | --- |
| 1 | 正常报告（含高/中/低各若干条） | 五个区块齐全，统计与明细条数一致 |
| 2 | `vul_list` 为空 | 显示「未检出风险项」，统计全 0 |
| 3 | 多文件（`file_name` 为数组） | 文件名用 `、` 连接，不报错 |
| 4 | 缺 `scan_meta` 部分字段 | 对应项显示 `-`，其余正常 |
| 5 | 某条漏洞缺 `suggestion` | 该条建议显示 `-`，不影响其他条 |
| 6 | `hit_content` 含 `<script>alert(1)</script>` | 以纯文本显示，不执行 |
| 7 | `level` 传非法值（如英文） | 走兜底样式，页面不崩 |
| 8 | 后端在线 + 已登录 | 从 `/api/reports/{report_no}` 渲染 |
| 9 | 后端关闭 | 自动降级 `sap_local_reports`，顶部提示本地报告 |
| 10 | 仅存在旧键 `scanResult` | 兼容渲染（若保留该兼容逻辑） |
| 11 | 无任何数据 | 空状态 + 返回扫描页链接 |
| 12 | 浏览器打印 | 只输出报告主体，无侧边栏和按钮 |
