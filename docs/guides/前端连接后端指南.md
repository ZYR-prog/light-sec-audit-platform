# 前端连接后端 · 傻瓜指南

> 目标：让现在这套纯前端页面用上 Flask 后端，同时保证后端挂了页面照样能用。
> 后端地址默认：`http://127.0.0.1:5000`

---

## 一、先搞清现状

- 现在的页面（`audit_demo/`）**没有调用任何后端接口**：扫描在浏览器里完成，结果存 `localStorage` 的 `scanResult`。
- 后端（`backend/`）接口已经写好，但没人调用。
- 所以"连接后端"不是修 bug，而是**给前端加一层 API 调用**，属于加分项。

原则只有一条：**后端能用就用，不能用就退回 localStorage，页面绝不能白屏。**

---

## 二、第一步：把后端跑起来

在项目根目录打开终端：

```bash
cd backend
pip install -r requirements.txt
python app.py
```

看到 `Flask 服务器已启动` 后，浏览器打开：

```
http://127.0.0.1:5000/api/ping
```

出现 `"message": "pong"` 就说明后端正常。数据库文件 `backend/data/security.db` 会自动创建。

> 想用管理员接口（审计日志），再执行一次：
> `python manage.py create-admin --username admin --password Admin@123456`

## 三、第二步：前端文件放在哪

只需要新增 2 个文件，都放在 `js/api/`：

```
js/api/
├── config.js    ← 后端地址 + token 的存取
└── request.js   ← 统一请求封装（自动带 token、超时、401 处理）
```

页面里的引入方式（现有页面已经是 module）：

```html
<script type="module" src="../js/pages/xxx.js"></script>
```

页面 JS 里这样用：

```js
import { request } from "../api/request.js";
```

**不要**在每个页面里各写一套 `fetch`，否则登录态、超时、降级逻辑会到处都是。

---

## 四、第三步：复制这两个文件

### `js/api/config.js`

```js
// 后端地址：以后换服务器只改这一行
export const API_BASE = "http://127.0.0.1:5000";

// token 存 localStorage，键名固定，方便所有页面共用
export function getToken() {
  return localStorage.getItem("sap_token") || "";
}

export function setToken(token) {
  if (token) localStorage.setItem("sap_token", token);
  else localStorage.removeItem("sap_token");
}
```

### `js/api/request.js`

```js
import { API_BASE, getToken } from "./config.js";

/**
 * 统一请求：成功返回后端 data，失败抛错（页面自己决定是否降级）。
 */
export async function request(path, options = {}) {
  const controller = new AbortController();
  const timer = setTimeout(() => controller.abort(), options.timeout || 6000);

  try {
    const res = await fetch(API_BASE + path, {
      method: options.method || "GET",
      headers: {
        "Content-Type": "application/json",
        ...(getToken() ? { Authorization: "Bearer " + getToken() } : {}),
        ...(options.headers || {}),
      },
      body: options.body ? JSON.stringify(options.body) : undefined,
      signal: controller.signal,
    });

    const json = await res.json().catch(() => ({}));
    if (!res.ok) {
      // 401 = 没登录/登录过期，调用方应退回本地数据
      throw new Error(json.message || "请求失败（" + res.status + "）");
    }
    return json.data;
  } finally {
    clearTimeout(timer);
  }
}
```

## 五、第四步：每个页面该干什么活

| 页面 | 要干的活 | 调哪个接口 |
|---|---|---|
| 登录 / 注册页（需要新增） | 登录或注册成功，把 `data.token` 存起来 | `POST /api/auth/register`、`POST /api/auth/login` |
| `scan.html` | 扫描完成后顺手保存一条历史；失败就只存本地 | `POST /api/history`，body 直接传 `scanResult` |
| `index.html`（Dashboard） | 进页面拉最近记录和统计；没登录就用本地 | `GET /api/history?pagesize=5` |
| 历史记录页（需要新增） | 列表、看详情、删除 | `GET /api/history`、`GET /api/history/<id>`、`DELETE /api/history/<id>` |
| `report.html` | 本地有 `scanResult` 就照旧渲染；URL 带 `?report_no=xxx` 时从后端读 | `GET /api/reports/<report_no>` 或 `GET /api/history/<report_no>` |

### 最小示例：扫描完成后保存

```js
import { request } from "../api/request.js";

window.addEventListener("scan:complete", async (e) => {
  try {
    await request("/api/history", { method: "POST", body: e.detail });
  } catch (err) {
    console.warn("后端保存失败，已保留本地结果：", err.message);
  }
});
```

### 最小示例：Dashboard 拉最近记录

```js
import { request } from "../api/request.js";

try {
  const page = await request("/api/history?pagesize=5");
  renderRecentList(page.list);   // 用你原来的渲染函数
} catch (err) {
  // 没登录或后端不可用 → 继续用 localStorage 的 scanResult
}
```

## 六、第五步：怎么判断"真的连上了"

按顺序做完这 5 条，就算接好了：

1. `http://127.0.0.1:5000/api/ping` 能返回 pong。
2. 注册一个账号，能在 `backend/data/security.db` 里出现（或再调 `/api/auth/me` 能返回用户名）。
3. 前端页面控制台执行 `localStorage.getItem("sap_token")`，能看到一串 token。
4. 扫描一个测试文件后，`GET /api/history` 能查到这条记录。
5. 把后端关掉再刷新页面：页面正常显示，只是少了"云端历史"——这就是降级成功。

首次快速验证（不用先写登录页，直接在浏览器控制台里跑）：

```js
// 1. 注册并保存 token
const r = await fetch("http://127.0.0.1:5000/api/auth/register", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ username: "test01", password: "Test123456" }),
});
const j = await r.json();
localStorage.setItem("sap_token", j.data.token);

// 2. 带 token 查历史
const h = await fetch("http://127.0.0.1:5000/api/history", {
  headers: { Authorization: "Bearer " + localStorage.getItem("sap_token") },
});
console.log(await h.json());
```

## 七、常见坑（照着排查就行）

| 现象 | 原因 | 解决 |
|---|---|---|
| 页面 `fetch` 报 CORS | 后端没启动，或地址写错 | 先确认 `/api/ping` 能打开；后端已开启 CORS |
| 请求一直 401 | 没存 token，或没加 `Authorization` 头 | 用 `request.js`，它会自动带 `Bearer` |
| 后端收到空 body | 少了 `Content-Type: application/json` | 用 `request.js`，已统一设置 |
| `file://` 打开页面请求失败 | 浏览器安全限制 | 用 `node serve.mjs 8123` 或 VS Code Live Server |
| 5000 端口被占用 | 已有别的程序在跑 | 换端口启动，并同步改 `config.js` |
| 保存时提示 `total 必须等于 vul_list 的条数` | `stat.total` 和漏洞数不一致 | 直接传 `scan.js` 产出的完整 `scanResult` |
| 查别人记录返回 404 | 这是故意的权限隔离 | 正常现象，不是 bug |

## 八、接口速查

| 方法 | 路径 | 是否要登录 | 作用 |
|---|---|---|---|
| GET | `/api/ping` | 否 | 探活 |
| POST | `/api/auth/register` | 否 | 注册（返回 token） |
| POST | `/api/auth/login` | 否 | 登录（返回 token） |
| GET | `/api/auth/me` | 是 | 当前用户 |
| GET / POST | `/api/history` | 是 | 历史列表 / 新增 |
| GET / PUT / DELETE | `/api/history/<id>` | 是 | 详情 / 修改 / 删除 |
| POST | `/api/reports/save` 或 `/api/reports` | 是 | 保存报告 |
| GET | `/api/reports` | 是 | 报告列表 |
| GET / PUT / DELETE | `/api/reports/<report_no>` | 是 | 报告详情 / 修改 / 删除 |
| GET | `/api/scanner/history` | 是 | URL 检测历史 |
| GET | `/api/audit-logs` | 是（仅管理员） | 审计日志 |

统一返回格式：

```json
{ "code": 200, "message": "success", "data": {}, "errors": [] }
```

- `401`：没登录 / token 过期 → 前端退回本地模式。
- `403`：登录了但没权限（例如普通用户查审计日志）。
- `404`：资源不存在，或不是自己的记录。
- `400`：参数不对，`errors` 里会写清楚是哪个字段。

---

## 九、最后记住三句话

1. **地址只写在 `config.js`**，以后换服务器不翻页面。
2. **所有请求走 `request.js`**，登录态和超时才不用每页重写。
3. **任何后端错误都要 catch**，然后继续用 `localStorage`，页面不能因为后端挂了就不能用。
