## 三、测试过程中发现并修复的问题

### 问题 1：VUL006 规则静默失效

- **现象**：`app.py` 中两处硬编码密钥一条都扫不出来，页面无任何报错。
- **定位**：控制台出现 `[scan.js] 规则 VUL006 正则非法，已跳过：Invalid regular expression ... Nothing to repeat`。
- **原因**：`exclude_pattern` 里写了 `***` 想匹配脱敏星号，但正则中 `*` 是量词，`***` 构成非法正则，整条规则编译失败。
- **修复**：改为 `\*{3}`。
- **验证**：重跑测试，T07 由 FAIL 转 PASS。

> **经验**：一条规则正则写错不会让程序崩溃，只会**静默失效**。所以必须有回归测试兜底。

### 问题 2：规则库路径依赖页面位置

- **现象**：页面挪到项目根目录后，规则库加载 404。
- **原因**：`fetch("./vulnerabilities.json")` 的相对基准是**页面 URL**，不是 JS 文件路径。
- **修复**：改为 `new URL("../../data/vulnerabilities.json", import.meta.url).href`。
- **验证**：`index.html`（根目录）与 `test-samples/mock-a-page.html`（二级目录）两种场景均正常。

### 问题 3：正则带 g 标志导致偶发漏报

- **现象**：同一文件连续扫描两次，结果条数可能不同。
- **原因**：`RegExp.test()` 在 `g` 标志下会推进 `lastIndex`，导致跨行匹配状态残留。
- **修复**：编译规则时统一 `replace(/[gy]/g, "")` 去掉这两个标志。

## 五、回归约定

> 每次修改 `data/vulnerabilities.json` 或 `js/core/scan.js` 后，**必须**在项目根执行：

```bash
node test-samples/selftest.mjs
```

要求：仍为 **12/12 通过**。

- 数字变化且是"规则故意变更" → 同步更新 `selftest.mjs` 里的 `cases` 期望值，并在本文档记录变更原因
- 数字变化但"规则不该变" → 说明改坏了，必须修回
