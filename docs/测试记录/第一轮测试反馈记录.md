## 四、发现的问题与反馈（按优先级）

### 🔴 P1：描述列显示什么，需要 A 定一下

**现状**：我的结果是两个字段都有——
- `description`：漏洞原理（如「SSH 服务开启密码认证，攻击者可暴力猜解口令」）
- `hit_content`：命中的那一行原文（如 `PasswordAuthentication yes`）

**建议**：
- 表格「描述」列 → 显示 **`description`**（原理说明，读者不用懂正则也能看懂）
- 「详情」弹窗 → 显示 **`hit_content`**（命中原文，方便定位）

**理由**：表格空间小，放原文意义不大（用户看不出哪里有问题）；原理说明更有信息量。

> 如果 A 倾向反过来，只需在 `renderTable()` 里换字段名，B 这边不用改。

---

### 🟡 P2：长描述会把表格撑变形

`description` 长度 40~90 字，直接塞进表格会让行高失控。

**建议 A 在 `css/components.css` 增加**：

```css
#result-table-body td:nth-child(5) {
  max-width: 320px;
  overflow: hidden;
  text-overflow: ellipsis;
  display: -webkit-box;
  -webkit-line-clamp: 2;      /* 最多两行 */
  -webkit-box-orient: vertical;
}
```

> 完整描述在详情弹窗里看，表格只做概览。

---

### 🟡 P3：进度条动画看不见（体验问题）

**现象**：纯前端扫描耗时 1~3ms，用户点完文件瞬间就到 100%，看起来像「没反应就结束了」。

**建议**（可放在 A 的 `audit-task.js`，不影响扫描逻辑）：

```js
// 保证进度条至少走 400ms，让用户感知到"正在扫描"
const minDuration = 400;
const t0 = performance.now();
const result = await scanText(text, file.name);
const rest = minDuration - (performance.now() - t0);
if (rest > 0) await new Promise(r => setTimeout(r, rest));
```

**为什么这不算"骗人"**：进度条本来就是反馈机制，扫描瞬时完成时给用户一个可感知的过程，是正常交互设计。答辩时也可以主动说明这一点。

---

### 🟡 P4：详情按钮的行为要和 A 的弹窗组件对齐

我这边做了三级降级：
1. 页面有 `window.openModal(html)` → 优先用 A 的组件
2. 没有 → 自己填 `#modal-container` 并 `display:flex`
3. 都没有 → `alert`

**需要 A 确认**：如果 C 的 `js/ui/modal.js` 已经可用，A 只要挂一行：

```js
import { openModal } from "../ui/modal.js";
window.openModal = openModal;   // B 的详情按钮会自动走你们的组件
```

## 五、已知的漏报风险（诚实说明，答辩可主动提）

| 场景 | 会漏报的原因 | 是否会补 |
|---|---|---|
| 配置项写成 `PasswordAuthentication=yes`（用等号） | 规则只匹配空白分隔 `\s+` | 可加 `\s*[=\s]\s*` 兼容 |
| 漏洞特征跨两行（如 `PermitRootLogin` 与 `yes` 分行） | 逐行匹配，不跨行 | 不补（成本高收益低） |
| GBK 编码的中文文件 | 按 UTF-8 读，中文可能乱码 | 待测 |
| 变形/混淆写法（如 `P a s s w o r d ...`） | 正则特征匹配的固有限制 | 不补，在 README「已知局限」中说明 |

> 已写入 `docs/scan-core-README.md` 第八节的「已知局限」，答辩时主动说明比被问出来好。
