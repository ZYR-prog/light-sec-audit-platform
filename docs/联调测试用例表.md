## 一、测试前准备（3 分钟）

1. 项目根目录已放 `serve.mjs`，执行：

```bash
node serve.mjs
```

2. 浏览器打开审计任务页（按实际路径调整）：

```
http://localhost:8000/pages/audit-task.html
```

3. 打开浏览器控制台（F12 → Console），**整个测试过程不要出现红色报错**。

> ⚠️ 不要双击 html 文件直接打开（`file://` 协议下 ESM 的 import 会被 CORS 拦截，扫描模块加载不出来）。

## 五、常见报错对照表

| 现象 | 原因 | 谁修 | 怎么修 |
|---|---|---|---|
| `Cannot use import statement outside a module` | 根目录 `package.json` 缺 `"type": "module"` | A / C | 加一行 `"type": "module",` |
| `Cross origin requests are only supported for protocol schemes` | 双击 html 用 `file://` 打开 | A | 用 `node serve.mjs` 起 http 服务 |
| 扫描结果为空，但文件确实有漏洞 | 规则库没加载成功 | B | 看控制台是否 `404 data/vulnerabilities.json`，检查 `RULES_URL` 相对路径 |
| 选文件后弹两次文件框 | `scan-start-btn` 的 click 被绑了两次 | A | 只保留一处绑定 |
| 表格出现 `undefined` | 字段名不匹配 | A | 用 `hit_content` / `description` / `rule_id`，勿自定义 |
| 弹窗打不开 | 页面里 `modal-container` 重复 id | A | 全局只保留一个 modal-container |
| 进度条瞬间到 100% | 没加动画延时 | A | 至少 400ms |
| 同一文件扫两次结果不一致 | 正则带 `g` 标志导致 `lastIndex` 漂移 | B（已修） | 规则编译时 `replace(/[gy]/g,"")`，当前版本已处理 |

## 六、已覆盖 vs 未覆盖（写进反馈文档用）

**已覆盖**
- 高危/中危/低危三档等级判定
- 注释行排除（`#` 开头不参与匹配）
- 脱敏后密码不误报（`***` 形式）
- 零误报基线（正常 SSH 日志）
- 多规则同文件聚合（app.py 5 条、web_config.ini 4 条）
- 多文件类型（conf / ini / log / py）

**未覆盖（第二轮补）**
- 超大文件（> 1MB）性能
- 二进制文件误传（.png / .exe）
- 编码非 UTF-8 的中文配置文件
- 行号定位精度（跨行匹配场景）
- 规则库扩到 18 条后的组合冲突
