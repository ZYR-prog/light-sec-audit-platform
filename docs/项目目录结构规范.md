## 一、设计原则

制定本目录结构遵循以下原则：

1. **前后端分离，后端可插拔** — 后端是独立文件夹，删除后前端照常运行
2. **按人分区，减少冲突** — 每人有明确的"主责目录"，尽量不交叉修改
3. **层级简洁，好找好记** — 目录深度控制在 3 层以内，命名直白
4. **数据唯一来源** — 漏洞库、基线库等共享数据只有一份，放前端 data 目录，后端通过接口读取
5. **文档集中管理** — 所有非代码文件统一放 docs 目录

## 三、各目录详细说明

### 3.1 根目录文件

| 文件 | 说明 | 负责人 |
|------|------|--------|
| `index.html` | 项目入口，自动跳转到 Dashboard 页面 | A |
| `README.md` | 项目说明文档 | C（整合） |
| `.gitignore` | Git 忽略规则 | C |
| `交付清单.md` | 最终提交时的文件核对清单 | C |

### 3.2 pages/ — 页面文件

- **存放内容：** 所有 HTML 页面文件
- **命名规范：** 全部小写，多单词用横线连接（kebab-case）
- **负责人：** A
- **说明：** 每个页面对应一个 HTML 文件，页面之间通过导航栏跳转

### 3.3 css/ — 样式文件

- **存放内容：** 所有 CSS 样式
- **拆分原则：**
  - `base.css` — 全局重置、CSS 变量、字体、通用工具类
  - `layout.css` — 导航栏、侧边栏、主内容区布局
  - `components.css` — 按钮、卡片、表格、弹窗等通用组件
  - `pages/` — 每个页面单独的样式文件，与 pages/ 里的 HTML 一一对应
- **命名规范：** 全部小写，横线连接
- **负责人：** A

### 3.4 js/ — JavaScript 模块

分四个子目录，按职责划分：

#### js/core/ — 核心扫描模块
- **负责人：** B（file-reader.js 由 A 负责）
- **说明：** 安全审计的核心算法，与页面无关，纯逻辑
- **要求：** 每个模块独立可测试，可以单独跑

#### js/ui/ — 通用 UI 组件
- **负责人：** C
- **说明：** 跟安全无关的通用交互组件
- **要求：** 组件化设计，提供统一的调用接口

#### js/api/ — 后端接口对接
- **负责人：** C
- **说明：** 所有跟后端通信的代码集中在这里
- **关键设计：**
  - `config.js` 里配置后端地址，统一管理
  - `request.js` 统一封装 fetch，自动处理超时、错误、降级
  - 后端不可用时，自动切换到 localStorage 模式
- **为什么集中放：** 以后如果改后端地址、加新接口，只改这里就行

#### js/pages/ — 页面逻辑
- **负责人：** A（融合对接主力）
- **说明：** 每个页面对应一个 JS 文件，负责把核心模块和 UI 组件"粘"到页面上
- **工作内容：** 绑定 DOM 元素、调用 core 里的扫描函数、调用 ui 里的组件、处理页面内的交互流程

#### js/utils/ — 工具函数
- **负责人：** C
- **说明：** 零散的工具函数，哪里都可能用到

### 3.5 data/ — 共享数据

- **负责人：** B（漏洞库）+ A（基线库、报告模板）
- **说明：** 所有数据文件放这里，前后端共用（后端通过读取文件或接口提供给前端）
- **数据格式：** 统一用 JSON，结构在 `js/core/data-schema.js` 里定义
- **为什么放前端目录：**
  1. 纯前端模式下前端直接 fetch 读取，不依赖后端
  2. 后端如果需要，可以读同一份文件，保证数据一致
  3. 删掉后端文件夹，数据还在，前端照跑

### 3.6 assets/ — 静态资源

- **负责人：** A
- **说明：** 图片、图标、字体等静态文件
- **注意：** 大图片尽量压缩，不超过 500KB

### 3.7 test-samples/ — 测试样例

- **负责人：** B
- **说明：** 各种测试用的样例文件
- **分类：** 按文件类型分文件夹，每种类型下分"含漏洞"和"正常"两组
- **用途：** B 自己测试扫描功能；答辩演示用；交付物的一部分

### 3.8 backend/ — 后端（可插拔）

- **负责人：** C
- **说明：** Flask 后端全部代码，独立目录
- **可插拔设计：**
  - 整个 `backend/` 文件夹可以独立运行
  - 删掉整个文件夹，前端不受任何影响（自动降级到本地模式）
  - 前端通过 `js/api/config.js` 里的开关控制是否启用后端
- **目录结构说明：**
  - `app.py` — 入口文件，注册路由、启动服务
  - `requirements.txt` — Python 依赖清单
  - `db/schema.sql` — 数据库表结构定义
  - `db/init_db.py` — 一键初始化数据库脚本
  - `models/` — 数据模型（数据库操作）
  - `routes/` — 路由（接口处理逻辑）
  - `utils/` — 工具函数
  - `tests/` — 接口测试脚本

### 3.9 docs/ — 项目文档

- **负责人：** C
- **说明：** 所有非代码类文档统一放这里
- **包含：** 系统分析说明书、分工流程、规范文档、过程记录、测试报告等

## 五、命名规范

### 5.1 文件命名

| 类型 | 规范 | 示例 |
|------|------|------|
| HTML / CSS / JS 文件 | 全小写，横线连接 | `audit-task.html`、`scan.js` |
| 数据文件（JSON） | 全小写，横线连接 | `vulnerabilities.json` |
| Python 文件 | 全小写，下划线连接 | `audit_record.py` |
| 图片资源 | 全小写，横线连接 | `logo-white.png` |
| 文档（Markdown） | 中文可读，无空格 | `目录结构规范.md` |

### 5.2 HTML 命名

- **id：** 小驼峰（camelCase），前缀表示类型
  - 按钮：`btnSubmit`、`btnUpload`
  - 输入框：`inputFile`、`inputUsername`
  - 容器：`containerResult`、`cardStats`
  - 表格：`tableVulns`
- **class：** 横线连接（kebab-case），语义化
  - `.btn-primary`、`.card-shadow`、`.text-danger`

### 5.3 JavaScript 命名

- **变量 / 函数：** 小驼峰 `scanFile()`、`vulnList`
- **常量：** 全大写下划线 `MAX_FILE_SIZE`
- **类 / 构造函数：** 大驼峰 `ScanEngine`

### 5.4 后端接口命名

- **URL：** 全小写，横线连接，REST 风格
  - `GET /api/history` — 获取历史记录列表
  - `POST /api/history` — 新增一条历史记录
  - `GET /api/history/:id` — 获取单条详情
  - `DELETE /api/history/:id` — 删除一条记录
- **返回格式：** 统一 JSON，包含 `code`、`message`、`data` 三个字段

## 六、可插拔后端的实现说明

### 6.1 物理隔离

后端所有代码都在 `backend/` 目录里，跟前端完全物理隔离。删掉这个文件夹，前端文件不受任何影响。

### 6.2 前端降级逻辑

```
js/api/
  ├── config.js     ← 配置后端地址 + 后端可用状态
  └── request.js    ← 统一请求封装，失败自动降级
```

**工作流程：**
1. 页面加载时，`config.js` 先调用 `/api/ping` 探活
2. 探活成功 → `backendAvailable = true`，所有请求走后端
3. 探活失败 / 超时 → `backendAvailable = false`，所有请求走 localStorage
4. 任何接口调用失败时，`request.js` 自动 fallback 到本地存储

### 6.3 关掉后端的方法

**方法一（推荐）：** 不启动后端服务，前端自动降级
- 最简单，什么都不用改
- 前端探活失败，自动切本地模式

**方法二：** 配置文件强制关闭
- 在 `js/api/config.js` 里设置 `forceOffline = true`
- 适合确定不用后端的情况

**方法三：** 彻底删除后端
- 直接删掉 `backend/` 文件夹
- 前端代码完全不用改，照样跑

### 6.4 数据共享

共享数据（漏洞库、基线库）只存一份在 `data/` 目录：
- 前端：直接 fetch 读取
- 后端：读取同目录下的文件（`../data/vulnerabilities.json`）
- 保证两边数据一致，不用维护两份
