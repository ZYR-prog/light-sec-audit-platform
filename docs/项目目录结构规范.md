# 轻量级安全审计平台 — 项目目录结构规范

**文档版本：** V2.0
**更新日期：** 2026-11-21
**适用范围：** 全项目成员

> 说明：V1.0 是开发前的规划结构（`pages/`、`css/` 等），实际开发中页面统一收敛到 `audit_demo/`。本版按**当前真实目录**重写，作为交付前的目录依据；原「命名规范 / 代码写法」章节已删除，本文只说明「哪里放什么」。

---

## 一、设计原则

1. **前后端分离，后端可插拔** —— 后端是独立文件夹，删除后前端照常运行。
2. **按人分区，减少冲突** —— 每人有明确的主责目录，尽量不交叉修改。
3. **层级简洁，好找好记** —— 目录深度控制在 3 层以内。
4. **数据唯一来源，但允许就近副本** —— 规则库只有一份；基线库、演示数据因页面就近加载保留副本，修改时同步。
5. **文档集中管理** —— 所有非代码文件统一放 `docs/`；交付核对放 `交付清单/`。

## 三、各目录详细说明

### 3.1 根目录文件

| 文件 | 说明 | 负责人 |
|---|---|---|
| `README.md` | 项目说明：功能、操作指南、模块介绍、难点与解决方案、结构说明 | C（整合） |
| `package.json` | 只声明 `npm test` 与 `npm run serve` 两个脚本，无第三方依赖 | C |
| `serve.mjs` | 零依赖静态服务器，解决 ES Module 必须走 http 的问题 | C |
| `.gitignore` | 忽略数据库、虚拟环境、缓存与系统文件 | C |
| `scan.html` | `audit_demo/scan.html` 的早期副本，相对路径会失效，**不作为入口** | A（遗留） |
| `README (1).md` | 早期 README 副本，保留备查，可删除 | C |

### 3.2 audit_demo/ — 页面与页面脚本

- **存放内容：** 全部 HTML 页面，以及只服务单个页面的渲染脚本。
- **负责人：** A。
- **说明：**
  - `index.html` 是整个平台的入口（仪表盘）。
  - `scan.html` 是核心业务页，业务逻辑放在 `js/pages/scan-page.js`，页面只保留 DOM 结构。
  - `dashboard-app.js`、`report-app.js`、`baseline-app.js` 是页面级脚本，通过全局 `Storage` 读取本地数据。
  - `app.js` 是 MVP 阶段遗留脚本，已不参与正式流程，保留备查。
  - `data/baseline.json` 是基线库的就近副本，页面按 `data/baseline.json` 加载。

### 3.3 js/core/ — 扫描核心

- **负责人：** B。
- **说明：** 纯逻辑模块，不碰 DOM，可脱离浏览器单独测试。
- **包含：**
  - `scan.js`：加载并缓存规则库、逐行正则匹配、等级统计、结果组装。
  - `data-schema.js`：等级常量、记录构造函数、结果校验，是全组唯一的数据契约来源。
  - `file-reader.js`：读取本地文件文本，内含 2MB 上限。

### 3.4 js/api/ — 后端对接

- **负责人：** C。
- **说明：** 所有与后端通信的代码集中在这里，页面不直接写 `fetch`。
- **包含：**
  - `client.js`：统一 base 地址、token 注入、超时、401 清理、网络失败降级。
  - `auth.js`：注册、登录、当前用户。
  - `reports.js`：报告的保存、列表、详情、删除。
  - `local-reports.js`：未登录或后端不可用时的本地报告存储（最多 20 条）。

### 3.5 js/pages/ — 页面逻辑

- **负责人：** A + C 联调。
- **说明：** 把页面 DOM、扫描核心、接口层「粘」起来。
- **包含：**
  - `scan-page.js`：审计任务页控制器——上传 / 拖拽、批量扫描、进度、结果渲染、登录弹窗、保存降级、历史记录。

### 3.6 js/ui/ 与 js/utils/ — 通用能力

- **负责人：** C。
- **说明：**
  - `js/ui/`：与安全业务无关的通用交互组件（弹窗、表格、标签页、折叠面板、面包屑）与本地存储封装。
  - `storage.js` 以普通 `<script>` 加载，暴露 `window.SapStorage`，内部 key 统一 `sap_` 前缀。
  - `js/utils/common.js`：日期格式化、字符串处理等零散工具，暴露 `window.Utils`。

### 3.7 data/ — 共享数据

- **负责人：** B（漏洞规则库、规则说明）+ A（基线库）。
- **说明：**
  - `vulnerabilities.json`：12 条漏洞规则，前端扫描与自测脚本共用同一份。
  - `scan-rules.md`：规则逐条说明，便于答辩与维护。
  - `baseline.json`、`demo-scan-result.json`：根目录副本，与 `audit_demo/` 下的同名文件内容一致，修改时需同步。

### 3.8 test-samples/ — 测试样例

- **负责人：** B。
- **说明：** 按类型分目录，每类包含「含漏洞」与「正常」两种样例，用于自测、答辩演示与回归测试。
- **用途：**
  - `selftest.mjs`：命令行回归测试，期望 7/7 通过。
  - `mock-a-page.html`：不依赖正式页面即可验证扫描模块的联调页。

### 3.9 backend/ — 后端（可插拔）

- **负责人：** C。
- **说明：** Flask + SQLite，独立目录，可整体删除。
- **分层：**
  - `models/`：数据库表定义（用户、报告、审计日志）。
  - `routes/`：只负责收参数、调服务、返回统一 JSON。
  - `services/`：业务校验、查库写库、写审计日志。
  - `utils/`：数据库连接与建表、密码哈希、token、鉴权装饰器、分页、统一响应。
  - `manage.py`：运维命令（建表、创建管理员、日志统计与清理）。
- **运行时生成：** `backend/data/security.db`（含 `-wal` / `-shm`）由首次启动自动创建，不提交仓库。

### 3.10 docs/ 与 交付清单/

- **负责人：** C。
- **说明：**
  - `docs/guides/`：安装、前后端对接、接口说明、报告渲染、联调用例等操作型文档。
  - `docs/测试记录/`：各轮测试记录与反馈。

## 五、可插拔后端说明

### 5.1 物理隔离

后端所有代码都在 `backend/` 下，与前端物理隔离。删除整个文件夹后，前端文件不受影响，只是失去登录与云端历史。

### 5.2 前端降级逻辑

```
页面启动
  └── client.js ping() → /api/ping（3 秒超时）
        ├── 成功 → 后端在线
        └── 失败 → offline，页面显示「后端不可用 · 本地模式」

任意请求
  ├── 网络失败 / 超时 → 返回 { offline: true }，调用方存 localStorage
  ├── HTTP 401        → 清除 token 与用户信息
  └── 其他错误        → 返回 message，页面提示，不破坏已有数据
```

### 5.3 关掉后端的三种方式

1. **不启动**：什么都不用改，探活失败自动降级（推荐）。
2. **换端口/地址**：前端通过 `window.SAP_API_BASE` 或 `sap_api_base` 指向新地址。
3. **彻底删除**：直接删掉 `backend/` 文件夹，前端照常运行。

### 5.4 数据共享

- 漏洞规则库只有一份：`data/vulnerabilities.json`，前端与自测脚本共用。
- 基线库有根目录与 `audit_demo/data/` 两份副本，属于页面就近加载的历史遗留，修改时需同步。
- 后端不读取前端数据文件，审计结果由前端提交到接口后写库。
