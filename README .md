# 轻量级安全审计平台
## 项目分工与开发流程
## 一、项目概述
本项目为轻量级安全审计静态网站平台，采用"前端保底、后端加分"的渐进式开发策略：

• **保底方案**：纯前端静态网站，包含 Dashboard、审计任务、安全基线库、审计报告生成、帮助页五大模块，全部功能通过前端 JavaScript 实现，无需后端依赖。

• **加分方案**：在纯前端基础上增加 Flask 后端，提供用户系统、审计历史记录保存、报告存储回看等功能。后端采用"可插拔"设计，若未完成或接口不可用，前端自动降级为本地存储模式，不影响核心功能使用。

## 二、项目简介：整体功能与特点

### 2.1 整体功能

平台由五个页面组成，覆盖"看 → 扫 → 学 → 出报告"的完整流程：

| 页面 | 文件 | 做什么 |
|------|------|--------|
| 仪表盘 | `audit_demo/index.html` | 展示高危 / 中危 / 低危漏洞统计卡片、风险分布图、最近扫描记录 |
| 审计任务 | `audit_demo/scan.html` | 上传文件（拖拽或选择）→ 启动扫描 → 进度反馈 → 结果表格 → 保存 / 查看历史记录 |
| 安全基线库 | `audit_demo/baseline.html` | 按名称 / 编号搜索基线规则，折叠查看每项检查说明 |
| 审计报告 | `audit_demo/report.html` | 按扫描结果生成结构化报告，支持打印 / 导出 PDF |
| 帮助与关于 | `audit_demo/help.html` | 使用指南、技术栈说明、项目信息（纯静态页） |

### 2.2 功能特点

1. **零安装**：纯静态网页，浏览器打开即可使用，不需要注册、不需要装客户端。
2. **未登录也能用**：游客可以直接上传文件扫描，结果保存在本机浏览器；登录后才保存到服务端。
3. **前后端可拔插**：后端是独立的 Flask 服务，不启动或挂掉时，前端自动降级到本地存储模式，核心扫描功能不受影响。
4. **扫描在浏览器端完成**：读取本地文件内容 + 规则库做正则匹配，文件内容不上传服务器，隐私友好，离线也能扫。
5. **结果可解释**：每条漏洞都带名称、风险等级、命中行号、命中内容、漏洞原理和修复建议。
6. **结果可带走**：支持生成结构化审计报告并打印 / 导出 PDF，方便交作业或留档。

### 2.3 技术选型（前端部分）

| 选择 | 理由 |
|------|------|
| 原生 JavaScript（ES Module） | 项目规模不需要框架，省掉构建工具和依赖安装；用 `import / export` 已经足够做模块拆分，浏览器直接支持 |
| Tailwind CSS（CDN 引入） | 不写构建配置、不装 Node 依赖，改样式即改即看；深色主题用工具类实现快 |
| 无打包、无构建 | 克隆下来起一个静态服务器就能跑，队友之间不存在"装环境"成本，也方便直接部署到 GitHub Pages |
| localStorage 作为降级存储 | 没有后端时仍能保存扫描历史，保证"打开就能用"的承诺 |

## 三、使用方法（操作指南）

### 3.1 环境准备

前端是纯静态页面，**必须通过 http 服务访问**，不能直接双击 html 文件（`file://` 协议下 ES Module 的 `import` 会被浏览器拦截）。

任选一种方式在**项目根目录**启动静态服务器：

```bash
# 方式一：Node（推荐，零依赖）
node serve.mjs          # 默认 http://localhost:8000
node serve.mjs 8080     # 指定端口

# 方式二：Python
python -m http.server 8000
```

浏览器访问：

```
http://127.0.0.1:8000/audit_demo/scan.html
```

### 3.2 可选：启动后端（登录、历史记录、报告存云端）

不启动后端也能完整使用扫描功能，只是历史记录存在本机浏览器。

```bash
cd backend
pip install -r requirements.txt
python app.py
```

后端默认监听 `http://127.0.0.1:5000`。如需改地址，可在页面里设置：

```js
window.SAP_API_BASE = "http://192.168.1.10:5000";
```

### 3.3 扫描一个文件

1. 打开「审计任务」页面（`audit_demo/scan.html`）。
2. 把文件拖到虚线框，或点击「📂 选择文件并开始扫描」。
3. 支持的文件类型：
   `.txt` `.log` `.html` `.json` `.conf` `.ini` `.cfg` `.py` `.yml` `.yaml` `.sh`
   单文件最大 **2MB**，支持一次选多个；不在列表里的文件需在文件选择器里切到"所有文件"。
4. 点击「🧪 扫描示例文件」可以用内置样例快速体验。
5. 进度条走完后，结果表格会列出：漏洞名称、风险等级、命中行号、描述，点「详情」可看命中内容和修复建议。

### 3.4 查看与保存历史记录

- **未登录**：扫描结果自动保存在本机浏览器（最多保留 20 条），页面下方「③ 历史审计记录」可以看到，刷新页面不丢。
- **登录后**：结果保存到服务端，换设备登录同一账号也能看到；列表支持刷新和查看详情。
- 页面右上角会显示后端连接状态（检测中 / 在线 / 离线），离线时会明确提示结果已转存本机。

### 3.5 登录 / 注册

1. 点击右上角「登录 / 注册」。
2. 没有账号时点「去注册」，注册成功后自动登录。
3. 登录态保存在浏览器本地，有效期 7 天；点「退出」清除。

### 3.6 生成审计报告

1. 完成一次扫描后，进入「审计报告」页面（`audit_demo/report.html`）。
2. 点击「生成报告」，页面会按风险等级排序渲染漏洞明细。
3. 点击「打印」，在浏览器打印对话框里选择"另存为 PDF"即可导出。


### 3.7 安全基线库

进入「安全基线库」页面，可按规则名称 / 编号搜索，展开查看每项基线的检查说明与整改建议。

### 3.8 常见问题

| 现象 | 原因与处理 |
|------|-----------|
| 页面空白 / 控制台报 CORS 或 `import` 错误 | 用 `file://` 直接打开了 html。改用 3.1 中的 http 服务方式访问 |
| 右上角一直显示「离线」 | 后端没启动或地址不对。确认 `python app.py` 已运行，端口与 `SAP_API_BASE` 一致 |
| 上传时看不到 `.conf` / `.py` 等文件 | 文件选择器默认按 accept 过滤；若仍有遗漏，手动切换到"所有文件" |
| 上传大文件提示超过 2MB | 单文件上限 2MB，请拆分或截取关键片段 |
| 登录后刷新变回未登录 | token 有效期 7 天；也可能是清除了浏览器站点数据 |

### 4.2 安全审计扫描模块

### 4.2 安全审计扫描模块

**规则库**：`data/vulnerabilities.json` 共 **18 条**规则（VUL001~VUL018），覆盖 SSH 配置、Web 服务配置、日志泄露、代码危险写法四类场景，等级分布为**高危 8 条 / 中危 7 条 / 低危 3 条**。每条规则是一个结构化对象：编号、名称、等级、匹配正则、排除正则、漏洞说明、修复建议。

**匹配机制**：逐规则、逐行做正则匹配，默认忽略大小写；正则编译前会移除 `g` / `y` 标志，避免 `lastIndex` 状态残留导致下一次匹配从错误位置开始、产生漏报。规则支持 `exclude_pattern`，用于排除注释行与合规写法——例如 `REAL_PASSWORD = os.getenv("APP_PASSWORD")` 这种从环境变量取值的**正确写法**，不会被"明文密码"规则误报。同一条规则在文件多个行命中时**全部收录**，不做去重合并，因为行号是定位依据。

**等级判定与统计**：每条规则自带中文等级（`高危 / 中危 / 低危`），扫描结束后按等级累加生成 `stat{high, mid, low, total}`，前端直接消费，后端原样存储，全程不做二次映射（避免中文等级与 high/mid/low 之间转换出错）。

**结果结构**：`vul_list` 每条含 `vid / vname / level / line / hit_content / description / suggestion / file_name`，其中 `hit_content` 截断至 200 字，防止超长命中内容撑破表格行高；`scan_meta` 记录 `file_name / total_lines / rule_count / rule_error_count / cost_ms / scan_time`，用于核对扫描完整性与性能。字段契约集中在 `js/core/data-schema.js`，并提供 `createVulRecord()` / `validateResult()` 做构造与校验。

**工程细节**：单条规则正则编译失败时**跳过该条并计入 `rule_error_count`**，不中断整轮扫描——保证一条坏规则不会让整个功能不可用。扫描本身是毫秒级：1.2MB 文件在页面端总耗时 < 2 秒，瓶颈在浏览器 `FileReader` 读文本，而非正则引擎。误报控制依靠两部分：4 份"应该 0 条"的阴性样例（干净代码、正常登录日志、注释掉的配置、0 字节空文件）作为回归护栏，以及 `exclude_pattern` 排除已知合规写法。

## 五、难点与解决方案

### 5.1 前端

> 以下 5 条由 C 起草，请 A 确认或补充（每条保留"现象 → 原因 → 解决"结构）。

1. **双击 html 页面打不开 / 页面空白**
   - 现象：控制台报 CORS 或 `import` 失败，扫描按钮无反应。
   - 原因：`file://` 协议下浏览器不允许 ES Module 跨源加载。
   - 解决：统一用 `node serve.mjs` 或 `python -m http.server` 起 http 服务访问，并把写进使用说明。

2. **本地存储封装与浏览器内置对象重名**
   - 现象：`window.Storage` 被覆盖后，部分浏览器行为异常。
   - 原因：`Storage` 是浏览器内置接口名，直接挂全局会冲突。
   - 解决：封装改名为 `window.SapStorage`，内部 key 统一加 `sap_` 前缀，避免与其他站点数据混淆。

3. **后端不可用时要"无感"降级**
   - 现象：后端没启动时，保存结果直接报错，页面卡住。
   - 解决：`client.js` 统一捕获超时 / 网络错误并返回 `offline` 标记；页面据此把结果写入 localStorage，同时在界面明确提示"已存到本机"，不打断扫描流程。

4. **页面之间怎么传扫描结果**
   - 现象：扫描页和报告页是两个独立页面，没有共享内存。
   - 解决：扫描完成后把结果写入 localStorage，报告页读取后渲染；未登录时同一条记录也用于历史列表。

5. **大文件把浏览器卡死**
   - 现象：选到几十 MB 的日志时页面无响应。
   - 解决：`file-reader.js` 在读之前先判断 `file.size`，超过 2MB 直接拒绝并提示；上传框的 `accept` 只列出可扫描的文本类后缀，减少误选。

6. **Chart.js 饼图"晃一下消失"**：
   - 现象：仪表盘初始用 Chart.js 每次 `destroy()` 再 `new`，导致图表闪一下就没。
   - 解决：只在第一次创建实例，后续用 `instance.data = newData; instance.update()` 只更数据不重建。
7. **Live Server 根目录不确定导致 fetch 404**：
   - 现象：右键不同位置启动 Live Server，项目根不同（有时是 `audit_demo/`，有时是项目根）。
   - 解决：fetch 用 3 路径 fallback（`data/x`、`../data/x`、`x`），总有一个能命中。

8. **ES Module 的 script 标签忘加 type="module"**：
   - 现象 HTML 里 `<script src="xxx.js">` 不识别 `import` 语法，浏览器报 Unexpected token 'import'。
   - 解决：每个用 ES Module 的 script 标签必须加 `type="module"`。

### 5.2 扫描核心

**正确写法被误报成漏洞**
   - 现象：测试样例里写了 `REAL_PASSWORD = os.getenv("APP_PASSWORD")`，这是从环境变量读取密钥的**正确做法**，却被"明文密码"规则命中，该用例报了 3 条（期望 2 条）。
   - 解决：给规则增加 `exclude_pattern` 排除分支，把环境变量取值、注释掉的配置行、示例占位符（`xxx`/`your-password`）统一排除。修完后该用例回到 2 条，同时干净日志那条仍稳定 1 条，**没有把功能改坏**。原则是**改规则、不改样例**——样例一旦为了迁就规则被改，就失去了暴露问题的价值。

2. **正则对象的全局标志导致漏报**
   - 现象：正则带 `g` / `y` 标志时，同一个 `RegExp` 对象被反复 `test()` 会保留 `lastIndex` 状态，第二次匹配从上次结束位置继续，出现"同一文件里交替命中、随机漏报"的现象，且极难复现。
   - 解决：规则加载时统一剥离 `g` / `y`，只保留 `i`（忽略大小写）；每条规则每次匹配都用干净的 `lastIndex`。这个坑排查成本很高但修复成本很低——正是"先写测试样例、再写规则"带来的收益。

3. **一条坏规则不能拖垮整轮扫描**
   - 现象：规则库是 JSON 数据，正则写错（转义不全、括号不配）会在 `new RegExp()` 时抛异常；若不加保护，一条坏规则会导致整份文件扫描中断，用户只看到"扫描失败"，无法判断是哪条规则的问题。
   - 解决：逐条编译与匹配都包在 `try/catch` 里，**单条失败只跳过该条**并累加 `rule_error_count`，其余规则照常跑完；`scan_meta` 里输出 `rule_count` 与 `rule_error_count` 两个计数，异常时前端也能显示"18 条规则中 1 条加载失败"，把问题暴露出来而不是掩盖。
￼
### 5.3 后端

1. **审计日志不能被随意篡改或删除**
   - 解决：`audit_logs` 只提供查询接口（仅管理员），不提供删除接口；`detail` 字段按白名单过滤，密码、token、cookie 等敏感键直接丢弃；默认保留 90 天，由管理脚本归档清理。

2. **登录 token 不能是随机串**
   - 解决：token 改为 HMAC 签名，服务端可校验完整性，防止伪造；密码使用 werkzeug 加盐哈希存储（兼容旧 SHA256 数据）。

3. **首次克隆后数据库打不开**
   - 现象：Git 不保存空目录，克隆后 `backend/data/` 不存在，SQLite 报"无法打开数据库文件"。
   - 解决：`utils/db.py` 初始化时自动 `mkdir(parents=True, exist_ok=True)`，并设置 WAL、`busy_timeout`、外键约束。

## 七、交付与运行速查

| 项目 | 命令 / 地址 |
|------|-------------|
| 启动前端 | `node serve.mjs`（或 `python -m http.server 8000`） |

| 扫描自测 | `npm test`（即 `node test-samples/selftest.mjs`） |
| 后端关掉后 | 前端自动降级本地存储，扫描功能照常 |
